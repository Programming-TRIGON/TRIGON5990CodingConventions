# TRIGON 5990 - Coding Conventions Repository

## Overview
This repository serves as the definitive guide for our software team's Java coding conventions. Consistency in our codebase is critical for ensuring that our robot code remains readable, maintainable, and easy to debug during the heat of competition.

## Why Clean Code & Consistent Conventions?

### The Cost of Messy Code
At the beginning of a project, ignoring standards might feel faster as people rush to churn out new features. However, if you don't maintain clean code, it quickly becomes cumbersome and unreadable. As readability drops, adding new features becomes incredibly difficult, and the team's overall efficiency drops.

Writing unclean code is even considered rude, it shows a lack of consideration for the teammates who have to read it, as well as your future self.

### The Benefits of Clean Code
* **Fewer Bugs:** Clean code directly leads to fewer problems and bugs in the software.
* **Empathy for the Reader:** Clean code feels like it was written by someone who was actively thinking about the person reading it.
* **Clarity:** Clean code is meant to be so clear that even someone who doesn't know how to code can understand it just from reading it.

### Why Consistency Matters
* **Prevents Chaos:** When code is written uniformly, the repository is much less likely to become a tangled mess.
* **Easy Navigation:** A consistent codebase is much easier to navigate and manage.
* **Faster Development:** Consistency speeds up the coding process. Because the design choices are already made for you, you spend less time thinking about formatting and more time solving actual problems.
* **How We Achieve It:** We build consistency through design patterns, documentation, language conventions, and having a definitive list of rules for every scenario, which is exactly what this repository provides.

## Repository Structure
This repository contains two types of resources:
1. **Executable Examples (`.java` files):** We have provided an actual Java class `GeneralConventions.java` that compiles and demonstrates our formatting rules in practice. The variable and method names within the file explicitly state the rules they are demonstrating.
2. **Documentation (`CONVENTIONS.md`):** A human-readable breakdown of the rules, utilizing tables and explanations to clarify our standards.

## How to Use This Repository
- **Read the Documentation:** Start by reading `CONVENTIONS.md` to familiarize yourself with the overarching rules regarding naming, ordering, spacing, and structure.
- **Study the Code:** Open the Java file provided in this repository.
- **Reference During Reviews:** Use this repository as a guideline when submitting or reviewing Pull Requests. If there is ever a debate about formatting, this repository acts as the single source of truth.

## Questions & Suggestions
If you have any questions regarding these conventions, or if you have suggestions for improvements or new rules, please feel free to raise an issue in this repository.
